# 📗 手順書：台風ページの「公開」と「自動更新」

> 台風情報まとめ（`typhoon-app/`）を**インターネットに公開**し、**Claudeを開かなくても中身が新しくなる**
> 状態にするための手順書です。むずかしい言葉は使いません。
>
> 💡 **この手順書の考え方は、防災ページ（`bousai-app/`）にもそのまま使えます。** 仕組みはほぼ同じです（4段構え・自動更新・自動公開）。

---

## 🎯 結論：のんさんの作業は「PRをマージする」だけ

以前は、GitHubの設定画面を開いて2か所いじっていただく予定でした。
その2か所を**自動でやる仕掛け**を入れたので、**もう設定画面を開く必要はありません**。

| やること | 誰がやる |
|---|---|
| GitHub Pages（公開）をオンにする | 🤖 自動（ワークフローがオンにします） |
| ページを公開しなおす | 🤖 自動（mainが新しくなるたび） |
| 台風データを1時間ごとに取り直す | 🤖 自動（毎時25分） |
| **PRをマージする** | 🙋 **のんさん（これだけ）** |

---

## 🧩 いま動いている3つの仕掛け

```
　　　　　  ┌──────────────────────────┐
毎時25分 → │ 🌀 台風情報の自動更新       │ 気象庁からデータを取って
　　　　　  │ typhoon-update.yml       │ data/latest.json を書き換え
　　　　　  └────────────┬─────────────┘
　　　　　               │ 終わったら
　　　　　  ┌────────────▼─────────────┐
mainが     │ 🌐 ページを公開           │ 最新の中身をインターネットへ
更新   →   │ pages-deploy.yml         │ （Pagesがオフなら自動でオンに）
　　　　　  └────────────┬─────────────┘
　　　　　               ▼
　　　　　  https://non-x2.github.io/non-x2/typhoon-app/
```

さらに、**ページを開いた瞬間にブラウザが気象庁へ直接**データを取りに行きます。
なので上の仕掛けが止まっていても、**開くたびに最新**が出ます（4段構えの①）。

## ✅ ちゃんと動いているかの確かめ方

### 1. 公開ページが開けるか
👉 https://non-x2.github.io/non-x2/typhoon-app/

- 開ける → ✅ 公開OK
- 「404 There isn't a GitHub Pages site here.」→ まだ公開処理の途中かもしれません。**5〜10分待って**もう一度。

### 2. 自動更新が動いているか
GitHubのリポジトリ画面 →上のメニューの **「Actions」** タブを開く。

| 見えるもの | 意味 |
|---|---|
| 🟢 緑のチェック | 成功。正常です |
| 🟡 黄色の丸 | いま動いている最中 |
| 🔴 赤い×印 | 失敗。下の「困ったとき」へ |

※ 「変更なし。コミットはしません。」と出て終わるのは**正常**です（気象庁の発表に変化がなかった回）。
※ 変化の有無は `typhoon-app/data` フォルダ全体で見ています。台風か警報の**どちらか一方だけ**変わった場合も、ちゃんとコミットされます。

### 3. ページが新しいデータで動いているか
ページ上部のバッジを見ます。

- 🟢 **⚡ 気象庁の発表：◯月◯日◯時** → 自動取得に成功しています
- 🟠 **⚠️ これはスナップショットです** → 自動取得ができず、手書きの予備の文章が出ています

### 💡 防災ページ（bousai-app）の場合の読み替え
- 公開URL：https://non-x2.github.io/non-x2/bousai-app/
- 自動更新ワークフロー：`.github/workflows/bousai-update.yml`
- 自動更新のタイミング：毎時**35分**（台風ページは25分）

## 🛟 困ったとき

### A. Actionsが🔴赤くなった／「Permission denied」「403」と出た
GitHubの**書き込み許可**が足りない可能性があります。1回だけ次の設定をしてください。

1. リポジトリの **Settings**（歯車マーク）を開く
2. 左のメニュー **Actions** → **General**
3. 下のほうの **Workflow permissions**
4. **「Read and write permissions」** を選ぶ → **Save**

### B. 公開ページがいつまでも404のまま
自動でオンにできなかった場合です。手動でオンにします。

1. リポジトリの **Settings** を開く
2. 左のメニュー **Pages**
3. **Source** を **「GitHub Actions」** にする

> ⚠️ 以前の案内にあった「Deploy from a branch」ではなく、**「GitHub Actions」** を選んでください。
> 公開のしかたを変えたためです。

> ✅ **この設定は 2026-08-02 に、のんさんが実施済み**です。初回だけはロボットの権限ではオンにできない
> ことがわかったためです（→ [`トラブル解決記録.md` T16](トラブル解決記録.md)）。
> 一度オンにすれば、その後はずっと自動で公開され続けます。もう一度この画面を開く必要はありません。

### C. しばらく放っておいたら自動更新が止まった
GitHubには「**60日間なにも動きがないリポジトリは、定期実行を自動で止める**」ルールがあります。
止まるとGitHubからメールが届きます。

👉 **Actions** タブ → 止まっているワークフロー → **「Enable workflow」** を押せば再開します。

※ ブラウザから気象庁へ直接取りに行く分（4段構えの①）は、これとは無関係にずっと動きます。

### D. 今すぐデータを更新したい
**Actions** タブ → 左の一覧から **「🌀 台風情報の自動更新」** → 右の **「Run workflow」** ボタン → 緑の **Run workflow**。
1分ほどで終わります。

## 🔒 プライバシーについて（2026-08-01に点検した結果）

| 調べたこと | 結果 |
|---|---|
| リポジトリの公開状態 | **もともと public（公開）**。GitHub上では以前から誰でも閲覧できる状態 |
| Pagesで新たに公開される情報 | **なし**（すでに公開済みのものを、見やすい形にするだけ） |
| のんさんの本当のメールアドレス | ✅ 入っていない。コミットは全部GitHubの**身代わりアドレス**（`...@users.noreply.github.com`） |
| パスワード・APIキー | ✅ なし |
| 電話番号・住所 | ✅ なし |

**Webページとして公開するのは、次の2つだけに絞ってあります。**

- `index.html`（入口ページ）
- `typhoon-app/`（台風ページ一式）

作業ログ・FF5の脚本・YouTubeの型などは、**GitHub上に置いたまま**でホームページには出しません。
理由は、検索エンジンに拾われる範囲を必要最小限にするためと、
README に載せているお問い合わせ用メールアドレスが**迷惑メール業者のロボットに拾われにくくする**ためです。

> 💡 **もっと隠したいとき**は「作業ログを非公開にしたい」とClaudeに伝えてください。
> その場合はリポジトリごと private にする（＝GitHub上でも見えなくする）方法をご案内します。
> ただし private にすると、無料プランではGitHub Pagesの公開ができなくなる点にご注意ください。
