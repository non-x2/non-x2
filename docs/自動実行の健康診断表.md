## 🔎 確かめ方（コマンド2つ）

```
# ① 毎時の3つ：main のコミットを見るだけで足りる（いちばん手軽）
git log origin/main --oneline -10

# ② ぜんぶ：ワークフローごとに最後の1回を見る（「completed success」なら元気）
gh run list --repo non-x2/non-x2 --workflow livecam-update.yml --limit 1
```

②の `livecam-update.yml` を上の表の別のファイル名に替えて、9回たずねます。

### 📐 2026-11-02 の実測（毎時の3つ・直近14日・mainのコミットの間隔）

`git log origin/main --since="14 days ago"` のコミット時刻の差を数えたものです。

| ワークフロー | コミット回数 | 間隔の中央値 | いちばん長かった間隔 | 3時間を超えた割合 |
|---|---|---|---|---|
| 🌀 台風情報 | 19回 | 5.6時間 | 10.8時間 | ほぼ毎回 |
| ⚡ 防災情報 | 11回 | 7.3時間 | 13.7時間 | ほぼ毎回 |
| 🚦 交通量 | 19回 | 5.7時間 | 10.5時間 | ほぼ毎回 |

💡 **読み取れること**：`cron:` に「毎時」と書いてあっても、実際に走るのは**おおむね5〜7時間おき**です
（GitHubが混んでいる時間帯の回は間引かれる）。3つとも**失敗はしていない**ので、
「成功したか」を見る点検では気づけない種類のズレです。
⚠️ ⚡防災だけ回数が少なめなのは、**地震・津波などに変化が無い回はコミットしない**つくりのため
（＝空いていても異常ではない）。だから許される間隔も24時間と長めにしてあります。
