# 全自動お任せモード（まとまった時間で一気に良くする）

## 一言で言うと

**「お任せで」と頼まれた板前**のイメージです。
毎日1品だけ出す庭師（/kaizen）に対して、こちらは**決めた時間の中でコースを組んで何品も出します**。
何を作るかはこちらで選び、最後に**まとめて1枚のお品書き（ドラフトPR）**にしてお渡しします。

## /kaizen との使い分け

| | 🌱 /kaizen（毎日の自己改良） | 🚀 /omakase（お任せモード） |
|---|---|---|
| 量 | 1日1件・100行以内 | 時間内に複数件 |
| 動くとき | 毎朝のRoutineが自動で | のんさんが「お任せで」と頼んだとき |
| 進め方 | 本体が1人で | 助手（サブエージェント）に手分け |
| 成果物 | 🌱ドラフトPR 1本 | 🚀ドラフトPR 1本（複数の改良入り） |

## 進め方（毎回この順番）

1. **開店（時間の約束）**：開始時刻をメモし、**制限時間（既定2時間。頼まれた時間があればそれ）**を宣言する。
2. **仕入れ（現状把握）**：読むのは3つだけ（トークン節約）。
   - 最新の `docs/作業ログ_*.md` **1枚だけ**
   - `docs/自己改良バックログ.md`（アイデア帳）
   - `docs/トラブル解決記録.md` は**見出しだけ**（Grepで `^## `）
3. **献立づくり（タスク選び）**：アイデア帳の「候補」を上から。足りなければリポジトリを軽く見回して安全な改良を足す。
   - 「要相談」「のんさんの判断待ち」は**献立に入れない**。
   - 読み取り専用の「点検」タスクは積極的に入れてよい（気づきはアイデア帳へ）。
4. **調理（手分け）**：独立したタスクは**助手（Sonnet）に並列で任せる**（/bunsan の型）。
   - **使ったモデルと体数は必ず日本語で申告する**。
   - 助手には「担当ファイル・変更してよい範囲・git操作はしない」を明記して渡す。
   - 助手同士が同じファイルを触らないよう担当を分ける。CLAUDE.md とアイデア帳は本体だけが編集する。
   - リポジトリをまたぐ大きな独立タスクだけ、新規セッション発行を検討（トークンを多く使うため乱発しない）。
5. **お品書き（PRづくり）**：変更をテーマごとにコミット → プッシュ → **ドラフトPR 1本**にまとめる。
   - PRタイトルは「🚀 」で始める。説明は中学生レベルの日本語で「なにを・なぜ・どう確認したか」＋改良の一覧表。
6. **アイデア帳の更新**（同じブランチで）：やった分を「📗 改良の記録」へ、点検の気づきを「候補」へ追記。
7. **仕込みの続き（自動継続）**：時間が残っていれば **send_later（自分あての目覚まし）を30〜40分後にセット**して一旦報告。起きたら状況を確認して次のラウンドへ。
8. **閉店（終了）**：次のどれかで店じまいし、**作業ログを書いて（または追記して）最終報告**する。
   - 制限時間が来た ／ 安全にやれる献立が尽きた ／ トークン残りが心配になった
   - 最終報告は結論ファースト：やった改良の一覧・PRリンク・未着手として残したもの。

## やってはいけないこと（安全柵）🚧

/kaizen の安全柵をそのまま引き継ぐ。特に：

- **マージしない**。ドラフトPRまで。反映するかは必ずのんさんが決める。
- **安全装置に触らない**：typhoon-app / bousai-app の警報判定・4段構えのフォールバック・「確認できていません」表示は変更しない。気づいたら「要相談」に書くだけ。
- **自動実行のワークフロー（.github/workflows/）を変えない**。提案止まり。
- **data/ の自動更新ファイルを触らない**。
- **「のんさんの判断待ち」案件を勝手に進めない**。
- **承認・確認ののんさんへのお伺いは最大10回まで**。戻しにくい操作（公開・削除・マージ）だけに使い、それ以外は自律で判断する。
- 時間ぎりぎりの新タスク着手はしない（中途半端が一番危ない。閉店30分前からは仕上げと報告に充てる）。

## 実行中の見せ方

- ラウンドごとに「今なにをしているか」を ⏳🔄 つきで日本語実況する。
- 助手に任せたら「Sonnet×4体に手分け中」のように**モデルと体数を申告**。
- 終わったら「✅完了しました」＋PRリンク＋改良一覧＋残り時間の報告。
