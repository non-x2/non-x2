# Git ガイド（のんラボ流）

このスキルには2つのモードがあります。頼まれた内容に合わせて使い分けてください。

- **教えるモード**：用語や流れの質問（「〇〇って何？」「どういう仕組み？」）
- **実行モード**：作業の依頼（「mainに反映して」「PRを作って」「マージして」）

どちらのモードでも：**日本語・中学生レベルの言葉・結論ファースト・例え話つき**で。

---

## 📖 教えるモード：まずこの説明を使う

### ひとこと辞典（例え話つき）

| 用語 | ひとことで言うと | 例え話 |
|------|----------------|--------|
| リポジトリ | 作品と履歴をぜんぶ入れた保管庫 | 「のんラボの書庫」 |
| main | 完成版の置き場所 | 本棚の「清書済みノート」 |
| ブランチ | mainを汚さない下書きコピー | 「下書き用のコピー用紙」 |
| コミット | 作業の保存＋メモ | 「ここまでやった、と日付印を押す」 |
| プッシュ | 手元の保存をGitHubへ提出 | 「下書きを事務局に郵送」 |
| PR（プルリクエスト） | 「この変更いかがですか？」の回覧板 | 「回覧板に下書きを添えて回す」 |
| ドラフトPR | まだ確認前ですよの印つき回覧板 | 「【確認待ち】の付箋つき」 |
| マージ | 下書きを完成版に合体させる | 「OKが出た下書きを清書ノートに転記」 |
| squashマージ | 途中の細かい保存を1つにまとめて合体 | 「下書きの試行錯誤は捨てて、完成形だけ転記」 |
| コンフリクト | 2人が同じ行を別々に直してぶつかった状態 | 「同じ欄に2人が別の字を書いた回覧板」 |

### 全体の流れ（5ステップ）

```
① ブランチを切る → ② 作業してコミット → ③ プッシュ → ④ ドラフトPR → ⑤ squashマージ
   （下書き開始）      （こまめに保存）      （提出）      （確認待ち）    （完成版に合体）
```

質問が1用語だけなら、その行だけかみ砕いて答えればOK。全体を聞かれたら5ステップ図から。
もっと詳しい資料は [docs/slides_git_claude入門.md](../../../docs/slides_git_claude入門.md) と [docs/指示書_Git操作手順書.md](../../../docs/指示書_Git操作手順書.md)。

## 🔧 実行モード：のんラボ流の型（必ずこの順で）

1. **最新のmainから新ブランチを切る**（名前は `claude/<内容>`。マージ済みブランチの使い回しは禁止）
2. 作業してコミット。**コミット末尾に必ず**：
   ```
   Co-Authored-By: Claude <そのセッションのモデル名> <noreply@anthropic.com>
   ```
3. プッシュして**ドラフトPRを作成**（タイトル・説明は日本語で）
4. **のんさんの「マージして」を待つ。勝手にマージしない**（マージ・削除・公開は必ず事前確認）
5. OKが出たら **squashマージ**。マージ後のブランチは再利用せず、次の作業はまた①から

### 作業前チェック
- [ ] [docs/トラブル解決記録.md](../../../docs/トラブル解決記録.md) にざっと目を通した
- [ ] 今いるブランチがmainではないことを確認した（main直編集はしない）

### よくあるつまずき（起きたら慌てず）
- **「Base branch was modified」でマージ失敗** → PRの状態を取り直して、もう一度マージすればたいてい成功（T4）
- **ドラフトのままだとマージできない** → PRを「準備完了（Ready for review）」に切り替えてからマージ
- **`gh` コマンドが使えない** → クラウド環境ではGitHub連携ツール（MCP）で同じことができる（T7）
- **コンフリクトが出た** → どちらの変更も生かす形で直すのが基本。直したらコミットしてプッシュ
- **やり直したい** → `git reset --hard` は使わない。mainから新しいブランチを切り直す（T2・T3）

### 実行中の見せ方
- 今どのステップかを ⏳🔄✅ つきで日本語実況する
- 終わったら「✅完了しました」＋PRリンク＋次にのんさんがやること（例：「マージして」の一言）を必ず報告
