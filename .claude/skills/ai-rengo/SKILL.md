# 外部AI連携スキル（よその専門家に意見を聞く）

## 一言で言うと

**「かかりつけ医（Claude）が、必要に応じてよその専門医に意見を聞きに行く」**イメージです。
診断と治療（判断とファイル編集）は必ずかかりつけ医が行い、外部AIには**相談だけ**をお願いします。

## 連携できる相手と得意分野

| 相手 | コマンド | 得意 | 費用 |
|------|---------|------|------|
| 🟠 OpenAI Codex CLI | `codex` | コードの相談・レビュー | 有料プラン前提が多い |
| 🔵 Gemini CLI | `gemini` | 調べ物・長文の相談 | 無料枠が大きい |
| 🟢 Ollama（ローカルLLM） | `ollama` | 軽い下書き・アイデア出し | 完全無料・ネット不要 |

> 入れ方・詳しい役割分担 → [`docs/指示書_外部AI連携セットアップ.md`](../../../docs/指示書_外部AI連携セットアップ.md)

## 進め方（毎回この順番）

1. **点呼**：`which codex gemini ollama` で、いま使える外部AIを確認する。
   - Ollamaがある場合は `ollama list` で入っているモデル名も確認する。
2. **正直に申告**：使える相手を日本語で報告する。**1つも無ければ**：
   - 「この環境には外部AIが入っていません」と正直に伝える。
   - ☁️ クラウドの部屋には外部AIは入らないので、代わりに **/bunsan（Claude助手）** を提案する。
   - 💻 ローカルで入れたい場合は `docs/指示書_外部AI連携セットアップ.md` を案内する。
3. **役割を決めて相談する**（1回の相談＝1つの質問文にまとめて、対話モードではなく**1発実行**で呼ぶ）：
   - Codex：`codex exec "質問文"`
   - Gemini：`gemini -p "質問文"`
   - Ollama：`ollama run <モデル名> "質問文"`
   - 質問文には必要な文脈（該当コードの抜粋など）を**必要最小限だけ**入れる。
4. **検品**：外部AIの答えを鵜呑みにしない。本体（Claude）が根拠を確かめてから採用する。
   採用・不採用と理由を日本語で説明する。
5. **申告**：「どのAIに・何を聞いて・どう使ったか」を必ず日本語で報告する（/bunsan のモデル申告と同じ作法）。

## 使いどころの例

| 場面 | 頼み方の例 |
|------|-----------|
| 設計で迷った | 「この2案、Geminiにも意見を聞いて」 |
| コードの見落とし探し | 「この差分、Codexにもレビューしてもらって」 |
| 無料でたくさん下書き | 「キャッチコピー20案、Ollamaに出させて」 |
| 事実確認のダブルチェック | 「この説明が正しいか、外部AIとクロスチェックして」 |

## やってはいけないこと（安全柵）🚧

- 外部AIに**ファイルの変更・git操作をさせない**。編集は必ずClaude本体が行い、検品する。
- **APIキー・パスワード・個人情報・非公開のメモを外部AIに渡さない**。渡してよいのはリポジトリ内の公開して困らない内容だけ。
- 外部AIの答えをそのままコミットしない（必ず本体が検証してから）。
- 外部AIツールのインストールや設定変更を勝手にしない（のんさんに指示書を案内して、のんさんが実施）。
- 費用が発生しうる相手（Codex等）への大量の呼び出しはしない。回数は必要最小限。

## 実行中の見せ方

- 点呼の結果（使える相手）を最初に表で見せる。
- 相談のたびに「🔵Geminiに◯◯を相談中…」のように実況する。
- 終わったら「✅完了しました」＋どのAIを何回使ったかのまとめ。
