# 📷 ライブカメラ台帳（livecam-db）

日本全国のライブカメラを **1か所にまとめた「台帳（データベース）」** です。
のんラボのどのページからでも、ここを読めば同じカメラ情報が使えます。

> 🔑 **このフォルダが「大もと」です。**
> 各アプリ（`traffic-app/` など）が持っているカメラ情報は、ここから配ったコピーです。
> 直したいときは、アプリ側ではなく**ここを作りなおして配りなおして**ください。
> （`data/offices.json` と同じ「正しい情報は1か所だけ」の考え方です）

---

## いま入っているカメラ

`python3 livecam-db/livecam.py info` でいつでも確認できます（2026-08-15 時点：**3,424台**／うち
**2,572台**はページ内に映像を出せる／一般道1,331・高速81・河川1,819・ダム114・海79）。

| 情報源 | 中身 | 利用条件 |
|---|---|---|
| 国土技術研究センター（JICE）道路チェック地図 | 国土交通省 各地方整備局ほかの**道路**ライブカメラ | 国が公開している地図データ |
| 国土技術研究センター（JICE）河川チェック地図 | 同じく**河川・ダム**のライブカメラ | 同上 |
| 海上保安庁 ライブカメラ | 灯台・港・岬の**海**のライブカメラ | **公共データ利用規約（PDL1.0）**＝出典を書けば再利用可 |

種類（`cat`）は `road`（一般道）／`expressway`（高速・自動車専用道路）／`river`（河川）／
`dam`（ダム）／`weir`（堰・水門）／`sea`（海）に分かれています。

> 🛣 **高速道路について**：`expressway` は**国が管理する**高速道路・自動車専用道路です
> （三陸道・京奈和自動車道・北近畿豊岡自動車道・名阪国道など **81台**）。
> **NEXCO・首都高・阪神高速などが管理する高速道路のカメラは入っていません**——
> 各社の利用規約で他サイトへの転載が認められていないためです（下の「取り込まなかった情報源」を参照）。
> 名前で見分けているため、「◯◯道路」で終わる路線（自動車専用道路のこともある）は `road` のままです。

> 📄 **出典の記載について**：海上保安庁のデータは PDL1.0 の条件として出典の記載が必要です。
> 台帳の `sources` 欄に出典を記録し、各カメラの `owner` にも「海上保安庁 ◯◯海上保安部」と入れています。

## 使い方

### コマンドで調べる

```bash
python3 livecam-db/livecam.py info                                        # 台帳の要約
python3 livecam-db/livecam.py near 35.681 139.767 --radius 10000          # 東京駅の近く（6台）
python3 livecam-db/livecam.py near 34.70 137.73 --radius 10000 --category river  # 河川だけ（10台）
python3 livecam-db/livecam.py search 国道1号 --pref 静岡県                 # 名前・場所・管理者で探す
python3 livecam-db/livecam.py route 40.81,140.45 40.83,140.73                # ルート沿い（五所川原→青森・3台）
python3 livecam-db/livecam.py search 天竜川 --with-image --json           # JSONで受け取る
```

### プログラムから使う（他のプロジェクトでも同じ）

```python
import sys; sys.path.insert(0, "livecam-db")
import livecam

db = livecam.load()

# ① ある地点の近くのカメラ（近い順）
for cam in livecam.near(db, 35.681, 139.767, radius_m=10000, limit=5):
    print(cam["name"], cam["place"], round(cam["distance_m"]), "m")

# ② ルート沿いのカメラ（出発地からの順）  route = [[緯度, 経度], …]
for cam in livecam.along_route(db, route, radius_m=1500):
    print(cam["name"], "出発から", round(cam["along_m"] / 1000, 1), "km")

# ③ しぼり込み
rivers = livecam.filter_cams(db, category="river", pref="新潟県", with_image=True)
```

## カメラ1台の形（スキーマ）

```json
{
  "id":    "jice-roads-00042",
  "src":   "jice-roads",
  "cat":   "road",
  "name":  "国道1号",
  "place": "静岡県静岡市清水区",
  "lat":   35.012345,
  "lon":   138.123456,
  "img":   "https://…/cam.jpg",
  "page":  "https://…",
  "owner": "中部地方整備局 静岡国道事務所"
}
```

| 項目 | 意味 |
|---|---|
| `id` | 台帳の中での通し番号 |
| `src` | どの情報源から来たか |
| `cat` | 種類（road / expressway / river / dam / weir / sea） |
| `name` | 路線名・河川名など |
| `place` | 市区町村（緯度経度から自動で付けています）。→ **2026-08-19 に、残っていた5台も付くようにしました**（下） |

> 🗾 **市区町村名が付かなかった5台を解決（2026-08-19）**
>
> 国土地理院は、その点に自治体の区域が無いと空の答えを返します（海の上・山の中）。
> そこで昔から「少しずらして聞き直す」しくみが入っていましたが、**ずらせる幅が最大1.3kmまで**でした。
> 実際に5台を1台ずつ調べたところ、**必要だったのは2.2km〜8.8km**で、この幅の外にありました。
>
> | カメラ | 場所 | 必要だった距離 | 付いた市区町村 |
> |---|---|---|---|
> | 国道112号 ×3 | 山形県の月山道路（峠） | 5.5〜8.8km | 鶴岡市／西川町 |
> | 赤川 | 山形県の山間部 | 5.5km | 鶴岡市 |
> | 野島埼灯台 | 千葉県・房総半島の南端（海上寄り） | 2.2km | 南房総市 |
>
> → `sources/base.py` の `_NUDGES` に **〜11kmまでの輪を4つ足しました**。新しい情報源は要りません。
> ふつうのカメラは今までどおり1回目で決まるので、**通信が増えるのはこの5台だけ**です（実測 12〜20秒／台）。
> ⚠️ ここまで広げた分は「厳密な所在地」ではなく「**いちばん近い市区町村**」です。詳しくは `sources/base.py` のコメントに書いてあります。
> ⚠️ **台帳のJSONに反映されるのは、次の自動更新（毎週火5:10）のとき**です。
| `lat` / `lon` | 緯度・経度 |
| `img` | **ページ内にそのまま出せる写真URL**。出せないカメラは `null` |
| `page` | 公式のカメラページ |
| `owner` | 管理者（◯◯地方整備局 など） |
| `also` | 別の情報源にも載っていた場合、その情報源（**無いカメラが大半**。`cam.get("also", [])` で読むこと） |

## 🔑 いちばん大事な仕組み：「https で開ける写真だけ `img` に入れる」

全国のライブカメラの写真URLは、**ほとんどが `http://`（暗号化なし）** で公開されています。
一方、のんラボの公開ページは `https://` なので、`http://` の写真をそのまま出そうとすると
ブラウザが**問答無用でブロック**します（「混在コンテンツ」という安全のしくみ）。

そこで台帳を作るときに、`http://` を `https://` に読み替えて
**1台ずつ実際に開いてみて**、ちゃんと画像が返るものだけ `img` に入れています。

開けなかったカメラも**消しません**。`img` を `null` にして `page`（公式ページ）を残すので、
アプリ側は「ここにカメラはあるけれど、映像は公式ページで見てください」と案内できます。

## 台帳の作りなおし方

```bash
python3 livecam-db/build.py      # 集める → 重複をまとめる → 写真を確認 → 市区町村を付ける
python3 livecam-db/export.py     # 各アプリに配る（traffic-app など）
```

写真の確認は3,000台以上に1台ずつアクセスするので**15〜20分**かかります。急ぐときは:

```bash
python3 livecam-db/build.py --no-verify     # 写真の確認をとばす（前回の結果を使う）
python3 livecam-db/build.py --no-geocode    # 市区町村の調べ直しをとばす
python3 livecam-db/build.py --only jice-roads   # 情報源をしぼる
```

**⚙️ 自動更新**：`.github/workflows/livecam-update.yml` が**毎週火曜 5:10（日本時間）**に
上の2つを実行します。カメラは増えたり減ったり故障したりするので、週1で見直す形にしています。

### 🇨🇦 BC州の取り込みの記録（2026-08-19）

定期調査（2026-08）で有望候補になっていたBC州を、実際に台帳へ入れました。**世界台帳の2つ目の情報源**です。

| 確かめたこと | 結果 |
|---|---|
| ライセンス | BC州の公式データカタログのAPIで `Open Government Licence - British Columbia` を確認 |
| データ | `https://www.drivebc.ca/api/webcams/` から鍵なしで **1,060台**（緯度経度つき） |
| 写真 | `https://www.drivebc.ca/images/<番号>.jpg` が本物のJPEGを返すことを3台で実測（HTTP 200・`image/jpeg`） |

> 📄 **出典の文言（消さないこと）**：
> `Contains information licensed under the Open Government Licence – British Columbia.`
> → `world-livecam/index.html` のページ下部と、台帳の `sources` に入れてあります。

#### ⚠️ いちばん大事な判断：`credit` 欄の仕分け

前回の調査記録には「**26台ほどは他所が提供しているカメラ**」と書いてありましたが、
実際に全件を調べたところ **82台に `credit` が入っていて、その多くは提供元ではなく運用メモ**でした。

| 中身 | 台数 | どうしたか |
|---|---|---|
| 他所が写真を提供している（TransLink・Parks Canada・City of Vancouver など） | **34台** | ❌ **取り込まない**（州のライセンスの外にある可能性があるため） |
| ただの運用メモ（「太陽光発電なので遅れます」「監視のため向きが変わります」など） | **48台** | ✅ 取り込む（州が自分で運用しているカメラ） |

**82台を丸ごと除くと、州のカメラ48台を誤って捨てることになります。**
逆に1台も除かないと、ライセンスの外の写真を載せてしまいます。
そこで「**他所が写真を提供していると読める言い回し**」だけを除く方式にしました
（`provided by` / `courtesy of` / `co-operation with` / `installed and maintained by`）。
安全側に少し広めで、電源提供の2台も除いています。

#### そのほかの判断

- **高速道路の区別はしていません**（全部 `road`）。アイオワ州は路線名が `I-80` のように高速と分かりますが、
  BC州のデータには高速かどうかを見分けられる印がありません。**分からないものを決めつけない**ためです。
  → **2026-08-19 に「路線番号で見分けられないか」を本気で調べ直し、やはり無理だと結論しました**（次の項目）。
- **止まっているカメラ15台は写真なし扱い**にしました（古い写真を「今の様子」として見せないため）。カメラ自体は残し、公式ページへの案内にしています。
- 場所は、データに入っている地域名を日本語にして「カナダ・BC州（ローワーメインランド）」の形にしました。

#### 🔎 調査済み：BC州の高速道路は路線番号では見分けられない（2026-08-19・結論＝実装しない）

> ⚠️ **この調査はもうやりました。同じことを繰り返さないでください。**

「路線番号から高速道路を判定できないか」を全件データ＋一次情報で調べ、**できないと結論**しました。

**カメラ1,026台の路線名は必ず `Hwy <番号> …` の形**（番号なしは12台）。上位10種は次のとおりです。

| 路線 | 台数 | 路線 | 台数 |
|---|---|---|---|
| Hwy 1 | 226 | Hwy 3 | 49 |
| Hwy 99 | 86 | Hwy 19 | 46 |
| Hwy 97 | 75 | Hwy 5 | 44 |
| Hwy 16 | 73 | Hwy 7 | 43 |
| Hwy 17 | 59 | Hwy 6 | 31 |

**なぜ判定できないのか（3つの理由）**

1. **BC州には「番号を見れば高速と分かる制度」が無い**。オンタリオ州の400番台のような仕組みは、
   BC州では1964〜1973年の短命な実験（Hwy 401/499）で終わり、いまは廃止済みです。
2. **同じ路線番号の中に高速と一般道が混在している**。たとえば Hwy 5（Coquihalla）が高速なのは
   Hope〜Kamloops の約186kmだけで、その北（Blue River・Valemount 方面）はふつうの2車線道路です。
   実際、台帳の Hwy 5 の44台のうち4台（Lempriere・Blue River・Messiter Summit・Wire Cache）は
   地域名が「北部」＝**非高速の区間**にありました。Hwy 97C・Hwy 1・91・99 も同じく区間で種別が変わります。
3. **州公式の分類はPDFと対話式地図でしか出ておらず**、こちらのデータの路線番号だけでは突き合わせできません。
   → https://www2.gov.bc.ca/gov/content/transportation/transportation-infrastructure/transportation-planning/highway-classification

つまり、路線番号で判定すると **実際は一般道の区間のカメラまで「高速」と誤表示することが確実に起きます**。
のんラボの約束「**分からないものを決めつけない**」に従い、全部 `road` のままにしました。

**それでもやるなら**：州の「Controlled Access Highways」対話式地図か LKI（Landmark Kilometre Inventory）から
キロポスト単位の区間データを取り、各カメラの緯度経度と突き合わせる必要があります。手間が大きいので、
「見分けられると便利」という要望が実際に出てから着手するのが妥当です。

### 🚫 写真として使わないホスト

元データ（JICE）の「写真URL」欄に、まれに**第三者のまとめサイトに置かれた画像**が混ざっています。
実際に `livecam.asia` の **2016〜2017年のスクリーンショット**が **43台ぶん**入っていました。

そのまま出すと、

1. **何年も前の静止画を「今の様子」として見せてしまう**（いちばん困る）
2. よそのサイトが置いているファイルを直接読みに行くことになる

ため、`sources/base.py` の `BLOCKED_IMAGE_HOSTS` に入れて**写真としては使いません**
（カメラ自体は残し、公式ページへのリンクで案内します）。

あわせて、`go.jp` / `lg.jp` / 生のIPアドレス以外のホストは**気づけるよう知らせます**
（止めはしません。鳥取県の雪みちNAVI のように、公的な情報を別ドメインで出している例もあるため）。
